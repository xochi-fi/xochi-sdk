# Changelog

All notable changes to `@xochi/client` are documented here. Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), versions follow [SemVer](https://semver.org/).

## [0.1.4] - 2026-10-29

### Changed

- Upgraded the schema runtime to Zod 4.6.7. The client, spec and reference suites pass against the same workspace client and schema version.

### Fixed

- **Machine**: status responses are applied only when their `intent_id` matches the active poll. A stale or misrouted terminal response for another intent can no longer complete or fail the current trade; the mismatch is ignored without advancing the poll, and a later matching response still applies.

## [0.1.3] - 2026-10-29

### Added

- Exported `NOT_SENT_SWEPT_ERROR` for hosts that need to identify the machine's expired-without-send Retry result.

### Changed

- **BREAKING: `IntentState.legsWithheld` is `boolean | null`** (was `boolean`): `null` means no status reply has established whether the current view is anonymous or owner-authorized. Migration: test `legsWithheld === true` before offering SIWE recovery; do not interpret `null` as an owner read.

### Fixed

- A live execute whose later status read returns `quoted` now enters the `not-sent` phase instead of remaining at "Still confirming". The first status read waits for the execute reply, so a pre-acceptance `quoted` row cannot produce that verdict. Status replies older than the latest answered attempt are ignored, preventing them from undoing a newer not-sent verdict.
- Returning to a visible tab restarts an exhausted in-flight status poll with a fresh budget. A live not-sent poll remains bounded by its original ceiling; only a resumed intent without a quote refills its budget on each `quoted` read.
- **Transport**: a valid server-directed `Retry-After` is honored up to the existing 600-second safety ceiling instead of being shortened to `retry.maxDelayMs`; the fallback exponential-backoff cap applies only when no valid integer delta-seconds interval is supplied (zero included). Pending quote deduplication now lasts for the whole request, including long server-directed retry waits.

## [0.1.2] - 2026-10-27

### Added

- Typed wire shapes and a zod decoder for Riddler's shielded terms preview (`POST /xochi/shielded/preview`, Riddler#1296): `ShieldedPreviewResponseSchema`, `ShieldedPreviewSchema`, `ShieldedFeeBreakdownSchema`, `ShieldedNetworkIdentitySchema`, `ShieldedCorridorSchema`, the `ShieldedPreviewRequestWire` / `ShieldedPreviewResponseWire` types and `decodeShieldedPreview(body)`, which also refuses a fee breakdown whose totals do not add up. Shapes only, with no transport method: the preview needs a `quote`-scoped Riddler credential, and the Xochi Worker proxy route that would expose it is a follow-up owned by xochi#635. A test holds the schemas' members to the vendored `wire/openapi.json`.

### Fixed

- A wallet signature prompt can be cancelled immediately, and every prompt now times out after 90 seconds. A dismissed WalletConnect request previously left consumers in `signing` forever with no retry action; `CancelSignRequested` returns the unchanged quote to its confirm surface, timeout returns to retry or quote refresh as its expiry allows, and any late signature is ignored.

## [0.1.1] - 2026-10-26

### Added

- `feeBreakdownReconcilable(feeBreakdown)` lets a `getQuote` result reach `assertFeeBreakdownInvariants` (the README example threw).
- `LayeredFeeBreakdownSchema` declares the served optional `discount { source: "tier" | "promo", bps, amount }` (xochi#584, served only when the quote request carried `promo_discount_bps > 0`). Shape-only: `assertFeeBreakdownInvariants` neither reads nor subtracts it, since `venue_fee`/`routing_fee` are already net of it. Previously it parsed through `.passthrough()` untyped.
- **Intent read capability** (xochi#563). `ExecuteResponseSchema` declares the optional `read_token` (32 random bytes, unpadded base64url; older servers omit it), surfaced as `ExecuteResponse.readToken` only when the response's `intent_id` is the executed intent. `getIntent` / `getIntentStatus` take `{ readToken }` and send it as the `X-Xochi-Read-Token` header, never in the URL, and this transport never sends it off the `baseUrl` origin (`redirect: "manual"`, which Cloudflare Workers accepts; an injected `fetch` that ignores it is the caller's leak). The server side is xochi#565 (merged as `0317e84`), served once it is deployed: a stealth intent read with the token gets the full record, and one without it (or an owner SIWE session) the status-only view; a token read of a shielded intent gets only the status-only view, as an anonymous read does (SPEC.md §5.1), and only a SIWE session for the intent's wallet reads its full record. A status-only view carries `substatus` only when it is `not_executed`. `getIntent` rejects a malformed `readToken`; `getIntentStatus` reads anonymously instead, so a caller bug cannot stall the poll. Every intent read, with or without the token, is pinned to the origin and refused as `RedirectRefused` otherwise; a refused token status read is retried without the token, following redirects natively, which also covers a browser's `opaqueredirect`. Rules: README "Transport". New exports `READ_TOKEN_LENGTH`, `READ_TOKEN_PATTERN`, `READ_TOKEN_HEADER`, `IntentReadOptions`, `takeApiErrorReadToken`, `RedirectRefused`, `WithheldIntentRecord`, `mapIntentRead`, `ExecuteReply`, `withheldSettlementConfirmed`.
- A malformed served `read_token` is dropped and the execute still parses (README "Transport").
- A failed execute whose body carries `read_token` for the intent it executed (the server serves it on a 502 when funds may have moved) hands it out once through `takeApiErrorReadToken(error)`; the token is never a property of the error, so error collectors, debuggers and property-inspecting loggers cannot reach it. The same channel carries the token of a 2xx execute whose other fields fail validation (`Invalid response format`), and of an error body cut by the read cap, read from its prefix by strict match. `ApiError.message` now carries a capped, redacted excerpt of the error body instead of the raw body (encodings and splits of the token included: a split across JSON's `\n`, `\r\n`, `\r`, `\t`, `\b`, `\f` or `\/` escapes, a lone CR, a token written after a backslash, whole or split once, whatever escape its first characters read as, and random pieces reading as names inside a chain of token pieces); backslashes as text stay as written (no escape starts at an escaped backslash, and nothing decodes to a backslash), and every error body is read only up to a cap (caps, redaction and what stays uncovered: README "Transport"); before, the token reached the raw message and was otherwise lost. When a token is lost for good: README "Transport".
- `getIntentStatus` surfaces the server's anonymous-view markers as `legsWithheld` and `settlementConfirmed`, and the machine shows a confirmed fill as delivered (`substatus: "filled"`) without changing `status` or `terminal`; when the marker counts (never on a failure, refund or unmapped status) is `withheldSettlementConfirmed`'s rule, applied by the transport, `getIntent` and the machine. `IntentState.legsWithheld` carries each status poll's verdict (an anonymous read sets it, an owner read clears it) so a host can offer wallet SIWE recovery.
- **Execute backpressure: the Worker's not-accepted refusal is resent, nothing else** (xochi#686). `ApiError.notAccepted` marks it (what counts, and the wait it carries in `retryAfter`: README "Transport"); `execute` stays single-attempt. A host passes the flag as `ErrorReport.notAccepted`; the machine then waits with no status read, shows the new signing slot `{ kind: "busy", retryAt, resend, of }`, and sends the identical `ExecuteRequest` again from the new `execute` timer, within `MAX_EXECUTE_RESENDS` (3) and `EXECUTE_RESEND_MARGIN_SECS` (5 s) before the earliest deadline (`decideExecuteResend`, `executeDeadline`), else "not sent yet" (below). Both constants are exported from the `@xochi/shared` mirror, as the Worker enforces them. A `retryAfter` more than a minute old (a delta passed where the absolute target belongs) gives up instead of resending at once, and the deadlines are judged on the host's clock (README "Fund safety"). `SignFlow.execute` (`ExecuteAttempt`) holds the request. Until the Riddler and Worker sides deploy the marker never arrives and nothing changes.
- **A not-accepted execute this client stops resending is "not sent yet", never Retry** (xochi#686). Every give-up (a 4th refusal, no or a stale `retryAfter`, a resend past the deadline), and the Worker's execute answer `200 { success: false, status: "quoted", reconciling: true }` (it ended its own claim but could not finish the intent), keeps the intent `executing` with the new `IntentState.notSent` (phase `not-sent`): the intent is `quoted` again, so its signed request stays executable until it expires. The poll runs on until the Worker ends the intent: usually its quote sweep first (an intent claimed and un-claimed, 90 s to about 6.5 min after the quote), otherwise the first read past the signed deadline plus `QUOTED_EXPIRY_GRACE_SECS` (60 s, new in the `@xochi/shared` mirror); `failed` with `not_executed` is Retry, and so is a 404 while "not sent yet" once `now` is past `unexecutedFinishAt(quote)` (the sweep deletes an intent nothing claimed after 30 minutes, and past the finish nothing can claim it); an earlier 404, one with no quote (a resumed intent) and a 404 anywhere else hold. A resumed `executing` intent that reads `quoted` is rebuilt as "not sent yet", its poll refilled by each `quoted` read, but only from a reply at least as new as every one answered (`PollState.answered`): a late `quoted` after a newer `executing` is no rebuild. Any other read ends the mark. Clearing the amount does not leave it; Reset does, and the README says when a host should not offer it (README "Fund safety").
- **The poll outlasts the Worker's finish of a never-claimed intent** (xochi#686). In `executing` the poll ceiling runs at least until `unexecutedFinishAt(quote)` (the later of the quote's `expiry` and the signed `deadline`, plus `QUOTED_EXPIRY_GRACE_SECS`) and one more poll, so an execute that never reached the Worker (a refused redirect, a timeout before any answer) reads `quoted` until the Worker finishes it `failed` with `not_executed`, then Retry. A read the intent cannot move to (`quoted` after an execute) no longer refills the poll budget (README "Fund safety").
- **After an execute, Retry only on the Worker's `not_executed`** (xochi#686). The `@xochi/shared` mirror gains `NOT_EXECUTED_SUBSTATUS` (its doc mirrors the one list of the marker's sources and serving points in xochi's contract doc) and an optional `substatus` on `ExecuteResponseSchema` and the stream frame (`IntentStatusFrameSchema`, `buildIntentStatusFrame`); `IntentRecord` / `WithheldIntentRecord` carry it as `substatus`. New: `IntentState.mayHaveMoved`, the phase `may-have-moved`, `failureMayHaveMoved`, and `ResumeRequested.substatus` for the record's marker as `getIntent` returns it at resume (README "Fund safety"). The rule covers every in-flight status (`POLL_INFLIGHT_STATES`), `awaiting_deposit` included: a deposit may have been sent unseen. `ApiError.inDoubt` says whether a failed execute answer cannot vouch that nothing moved for the executed intent: `false` only on the Worker's three answers that speak for the intent (the not-accepted 503, its 502 `failed` marked `not_executed`, its 409 `promo_unavailable`); `true` on every other answer, since another request may hold the intent: every other 4xx (a parse 400, a 403 `api_key_intent_mismatch`, a signature 401 and the signed-deadline 400 included), every 429 and 5xx, and any answer carrying a read token or `reconciling: true`. No error text is read (README "Transport"). It is for the host's copy and logs; the machine does not read it.

### Changed

- **BREAKING: hosts must schedule the new `execute` timer and render the new `busy` signing slot** (`TimerName` gains `"execute"`, `SigningSlot` gains `{ kind: "busy"; retryAt; resend; of }`). An exhaustive switch over either union stops compiling until it handles the new member; a host that silently ignores the `execute` timer resends up to `STATUS_POLL_MS` (4 s) late, from the first poll tick or returning tab at or after the resend time, and stops resending ("not sent yet") when that lands inside the deadline margin (README "State machine"). Migration: schedule `execute` like the other timers (one-shot, `ms` from the effect) and render `busy` as a countdown to `retryAt` (phase `submitting`).
- **BREAKING: after an execute, a `failed` offers Retry only with `substatus: "not_executed"`.** Every other `failed` after an execute or a revealed deposit address, from the poll, a stream frame or a final execute reply, bare or granular, ends at once in the terminal "may have moved" view (`IntentState.mayHaveMoved`, phase `may-have-moved`): no Retry, the poll stopped, no quote and no cleared amount out until Reset. A resumed `failed` ends there too unless `ResumeRequested.substatus` is `not_executed`. Before, a `failed` poll after a thrown execute offered Retry. Until the Worker serves the marker (xochi#686), every `failed` after an execute ends in that view. Migration: render `may-have-moved` with Reset only and `not-sent` without Retry (suggested copy for both: README "Fund safety"), handle both in an exhaustive `SwapPhase` switch, and pass the `substatus` `getIntent` returns at resume.
- **`execute` is pinned to the `baseUrl` origin**: sent with `redirect: "manual"`, it follows no redirect and rejects any redirect shape, foreign answer, or answer naming no `url` (a response an injected `fetch` built, which may stand for a followed redirect) with `RedirectRefused`, unread (no result, no token); a token read refuses an answer naming no `url` too, and a token-less intent read refuses a `redirected` response that names no `url` (README "Transport"). An injected `fetch` must return the response it fetched; the first answer naming no `url` (normally the first quote) is logged once at `error`, and the refusal's message names the cause.
- **BREAKING: `getIntent` returns `IntentRecord | WithheldIntentRecord | null`** (was `IntentRecord | null`): a withheld read is the status-only `WithheldIntentRecord` (`legsWithheld: true`) instead of an `IntentRecord` with defaulted tokens, amounts and fees, its `status` decoded as a status poll decodes it (`fill_failed` reads `failed`; an unmodelled status reads `executing` with `unmapped: true`). Migration: narrow with `if (record && !record.legsWithheld)` before reading traded values.
- **BREAKING: `IntentRecord.fromAmount`, `toAmount`, `createdAt` and `updatedAt` are optional** (were `string`) and absent when the server does not serve them, never defaulted to `"0"` / `""`: a missing amount is not zero (SPEC.md §5.1). Code that assigns one to a `string` or calls a string method on it stops compiling. Migration: handle `undefined` (show the value as unknown, never as `0` or an empty date), e.g. `record.fromAmount ?? null`.
- **BREAKING: `ExecuteReplied` carries the execute response without its read token** (`result: Outcome<{ response: ExecuteReply }>`, where `ExecuteReply` is `ExecuteResponse` with `readToken?: never`), so no machine message, model, effect or replay log holds the bearer secret. The machine still derives the failed-vs-in-doubt verdict (#226) itself and never throws on a reply it cannot read; which replies are in doubt: README "Fund safety". Migration: `const { readToken, ...response } = await xochi.execute(request)`, keep `readToken` outside the machine, dispatch `{ type: "ExecuteReplied", flow, result: { ok: true, response } }`. A `failed` reply is final only with `reconciling: false` (Retry only with `not_executed`, else "may have moved"); without the flag it is in doubt and polled (README "Fund safety").
- **`QuoteReferralSchema` is a union** matching xochi#618: the named `{ code, name }` line (served only to a caller signed in as the quoting wallet) or the neutral `{ neutral: true, note: REFERRAL_NEUTRAL_NOTE }` line (a `ref` was applied, the caller is not the quoting wallet). New export `REFERRAL_NEUTRAL_NOTE`. Consumers that read `referral.code` must narrow on `"code" in referral` first.
- **Depends on the workspace `@xochi/signer`** (was the unpublished `@riddler/signer`).
- **Version 0.1.1**, past every pre-fix commit (which declare the never-published 0.1.0).
- Takes `Promise.withResolvers` from `ES2024.Promise`; built with TypeScript 6. `package.json` gains description, keywords and homepage.
- `package.json` declares `repository` with its `directory`, as `npm publish --provenance` requires; releases publish from `.github/workflows/release.yml` with provenance on a `client-v*` tag.
- The tarball ships this `CHANGELOG.md`.
- `IntentRecordWire.aztec_note_hash` is `string | null` (optional), matching the Worker, which serves `null` unless the intent settled shielded; `mapIntentRecord` maps `null` to an absent `aztecNoteHash`.
- The `settlementType` description states served shielded behaviour: unavailable while `SHIELDED_SETTLEMENT_LIVE` is off, and when offered recipient-private only (amount, token, solver, timing and source activity public or inferable). `IntentRecordWire.aztec_note_hash` is documented as the Worker's intents-row field (not `/xochi/*`).

### Removed

- `QUOTE_CACHE_TTL_MS` / `TRADING.quoteCacheTtlMs` (30 s, the value the transport's 15 s default avoids).
- `ExecuteRequest.aztecProof` and the `aztec_proof` key of the `execute` body. Nothing set it, so the body always serialized it as undefined (omitted); no producer or consumer reads it (SPEC.md §3.2). The exported `ExecuteRequest` type stays; a caller passing `aztecProof` in an object literal now gets a TypeScript excess-property error.

### Fixed

None of these was published with the old behavior.

- Injected transport logging receives a projection of an `ApiError`, never the error object itself.
- **Machine**:
  - A new amount, trade/wallet context change, Reset or `ResumeRequested` drops in-flight quotes (a late reply overwrote the corrected quote; a Tron allocation waiting on sign-in re-quoted over the resumed deposit intent). Entering signing, awaiting-deposit or in-flight drops every quote in flight, and a reply arriving after quoting is logged and dropped.
  - `RefreshRequested` is ignored in those states, and `AllocateRequested` (resolving its ref `ok: false`) outside idle/pending/quoting/quoted; a refresh over the open wallet prompt could fail an executing swap that then never reached `completed`, and an allocation after a completed deposit could reopen it as `quoted` and reveal the settled address again. A failed allocation never reopens a trade as `quoted`. Leaving `executing` ends the sign ceremony, and a status update that moves `signing -> executing` abandons it (a pull approval and signature prompt fired for a swap already in flight).
  - A served `preview` that disagrees with the request is refused, any quote carrying `eip712` is signer-checked, and Confirm is gated on `canSignQuote`. A non-null `escrow` envelope (`QuoteResponse.escrow`) reaches the signer refusals.
  - A held quote cannot be signed, or its deposit address revealed, once the form's amount or trade (chains, tokens, settlement, trust score, slippage, recipient, refund, stealth keys, wallet) no longer matches its quote (`holdsCurrentQuote`; the signing slot reads `unavailable`). The trade key uses the quote request's normalisation, so an edit that leaves the request unchanged (`""` recipient, stealth keys under public settlement) keeps Confirm enabled. The origin-pull solver pin and approval amount use `quotedFromAmount`, not the live amount.
  - A visible stealth hold clears the held public quote; `view().settlement` shows the held quote's settlement (`IntentState.quotedSettlement`).
  - Confirm on a deposit route with under `DEPOSIT_MIN_WINDOW_SECONDS` of attested window left expires instead of revealing the address.
  - `StreamStatus` frames for another intent are ignored; "Sign 2 of 2" after expiry lands in `expired` instead of stranding in `signing`; clearing the amount ends a half-finished two-step ceremony.
- **Transport**: quote and execute bodies are validated against `QuoteResponseSchema` / `ExecuteResponseSchema` (undeclared top-level keys tolerated), so a malformed field is `Invalid response format`, not a raw `TypeError` or silent cast. The per-attempt timeout covers the body, so a stalled body no longer hangs `getIntentStatus` / `execute`; a timed-out or aborted request cancels its body even when an injected `fetch` ignores the signal, and unread non-ok bodies are cancelled. A reason phrase the `Response` constructor rejects (non-ASCII, control bytes) no longer throws out of the re-wrap.
