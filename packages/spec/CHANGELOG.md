# Changelog

All notable changes to `@xochi/spec` are documented here. Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), versions follow [SemVer](https://semver.org/).

## [Unreleased]

### Added

- **ERC-8262 provider protocol** (SPEC.md §10, xochi-sdk#37): `erc8262/provider-discovery.schema.json` for `/.well-known/erc8262-provider.json`, `erc8262/provider-evidence.schema.json` for `/v1/erc8262/evidence/{evidenceId}`, and `erc8262/vectors.json` (+ `vectors.schema.json`), generated by `npm run generate:erc8262`; `test/erc8262-provider.test.ts` validates the set with `ajv` (new devDependency) and re-derives every outcome. Signing is out of scope.
  - Vectors: native, gateway, alias and impostor fixtures, 25 schema rejections, 140 evaluation cases and 12 quorum cases.
  - Identifiers: `sourceId`, `claimType`, `trustDomainId` (never an IP literal) and `attestorProviderId` (the Oracle `providerId`, at most 2^256 - 1). Protocol constants ship in `vectors.json` `limits`.
  - Neither document is signed: the consumer's allowlist pins each trust domain to its attestor per deployment, evidence must come from the discovery host, and acceptance authorizes nothing until the Oracle-verified proof it feeds matches it (`proof_mismatch`): the evidence's attestor and artifact (type 4) or the signer hash of the key named by `keyId` (types 7/8/9), a proof timestamp in [`issuedAt` - 60 s, `expiresAt`), and a live, unrevoked Oracle attestation; public inputs are rendered as the spec states (`submitter` as a 20-byte address). Quorum counts distinct attestors per (`claimType`, `proofType`), every member evaluated against the same consumer state.
  - An announced `evidenceId` is checked against its schema rule before the URL is built (`evidence_id_invalid`) and the body must carry the requested id (`evidence_id_mismatch`). Fetch contract: https, no redirects, 10 s timeout, 64 KiB / 8 KiB body caps, no cached copies. A `410` and a schema-valid `status: "revoked"` body carrying the announced id are final, checked right after the origin check and recorded even while discovery is unavailable or invalid; `404`, every other failure and a `200` whose body fails its schema (incl. an unsupported `protocolVersion`) are unavailable.
  - Rotation and time: one clock-skew rule (60 s, tolerated only where a check would refuse because another party's clock is ahead; never on expiry or retirement; exact between instants of one clock). A key is current until 60 s before its `notAfter`, and providers announce `notAfter` ahead and switch the Oracle at it; retired credential-root keys' evidence lives to its `expiresAt` while the Oracle holds its root (48 h `CREDENTIAL_ROOT_TTL`); retired signed-signals keys end at `notAfter`; evidence lives at most 365 days; a discovery `updatedAt` more than 60 s ahead is refused and never recorded (`discovery_from_future`); timestamps are at most 2^32 - 1. An attestor the Oracle guardian denied is refused (`attestor_denied`).
  - Observation store: keyed by (`trustDomainId`, `evidenceId`), durable and shared by every granting instance, with atomic, monotonic writes (atomic maximum for `updatedAt`, insert-if-absent records) and read-your-writes; it remembers revocations, key revocations by `keyId` and key material, and the highest recorded `updatedAt`. Every evaluation case pins what the consumer records (`expected.records`), and `follows` chains a case to the earlier one whose records it starts from. A held grant is re-evaluated every `revocationCheckSeconds`; one whose re-evaluation cannot complete is suspended, not revoked, and nothing is recorded. Concurrent identical fetches may be coalesced; re-fetches are jittered and failures backed off.
- **Moved in from the archived `axol-io/riddler-sdk`** (snapshot, no history) as `@xochi/spec` (was `@riddler/spec`). Every vector digest, signature, typehash and domain separator is byte-identical; only `description` strings naming a package changed. EIP-712 domain and contract names (`Xochi`, `RiddlerSolver`, `RiddlerFiller`, `RiddlerEscrow`, `SolverBond`) are unchanged.
- `README.md`: how to consume the spec (moved from the repo root README).
- **`conformance/shielded.json` + `shielded.schema.json`** (xochi#633, xochi#635): vectors for the shielded settlement contract v1 typed encodings approved 2026-10-18 (xochi `shielded-execution.md` §7), with the `NetworkIdentity` encoding `NetworkIdentity(uint256 aztecChainId,uint256 protocolVersion,address rollupAddress,uint256 l1ChainId,bytes32 genesisOrNetworkDigest)` approved by the product owner on 2026-10-19 (`protocolVersion` = the numeric Aztec rollup version; the §7 record lands in a separate xochi PR). Covers the `NetworkIdentity` hashStruct, the salted `Domain (binding)` (`Xochi Shielded Recipient`) and `Domain (terms)` (`Xochi Shielded Terms`), `RecipientBinding` struct hashes, digests and source-wallet signatures (public test keys), and refusal cases for Aztec `bytes32` values (zero, not below BN254 r; magnitude alone, since EVM/Aztec provenance is enforced by descriptor/address derivation) and amounts (`0 < x <= 2^128 - 1`, canonical decimal). The generator imports nothing from `@xochi/signer`: it derives every value from §7's literals with ethers primitives and writes its refusal expectations as data, and `@xochi/signer` is tested against the committed file. Regenerated by `npm run generate:shielded`, gated in CI. No vector for ShieldedTermsV1, manifestDigest, descriptorDigest or the recipient message: §7 leaves them open, and the file's `open` array names them. Network, corridor and Aztec values are fixtures. Additive; no existing vector changes.

### Changed

- **Version 0.9.0** (MINOR, additive; SPEC.md §0.3). No taker signed struct, fee artifact, served wire field or existing vector changes. Riddler must advertise `spec_version: "0.9.0"` in lockstep, or the nightly `spec_version` probe reports DRIFT. The `@xochi/sdk` and `@xochi/reference` dev pins move to `0.9.0`.
- **Wire contract refreshed to served spec 0.8.0** (from axol-io/riddler-sdk#150): `wire/openapi.{json,sha256}` replaced by the prod refresh (Canton `ChainAddress` branch, chain `253340876`, `cvm`/`canton_party`, escrow schemas, `escrow_refused`/`escrow_unavailable`); SPEC.md §3.2/§3.3/§3.5/§6 follow the served shapes.
- **Wire contract refreshed again (2026-10-12, `0 BREAKING, 2 STALE`)**: the served `0.8.0` gained xochi#584's optional `QuoteRequest.promo_discount_bps` and `LayeredFeeBreakdown.discount { source, bps, amount }`; `wire/openapi.{json,sha256}` carry them and SPEC.md §3.3/§4.5 describe them. No vector, schedule or reconciliation rule changes; the version stays `0.8.1` (SPEC.md §0.3).
- **SOLVER-RFC `0.5.0-draft`** (clarification, `rfcVersion` unchanged, from axol-io/riddler-sdk#151): the quote-time `minOutput` is the quote less a venue-wide announce margin (`SOLVER_ANNOUNCE_FLOOR_BPS`), never a taker-chosen value such as `slippage_bps`.
- **SOLVER-RFC `0.5.0-draft`: the announcement is public-only** (producer withdrawal, `rfcVersion` unchanged, xochi-sdk#29 with Riddler #1200). The SDK-side narrowing ships here. The producer withdrawal is `[PROPOSED]` until Riddler #1200 (PR #1302) merges to `master` (the RFC legend's meaning of `[IMPLEMENTED]`). Separately, the privacy property holds only once it is deployed and the feed has drained. §§2.2/4.2 narrow `IntentAnnouncement.settlementPreference` to the single required value `"public"` and withdraw `recipientCommitment`; §2.4 admits private flow back only under a separately reviewed encrypted or commit-reveal design. Rollout order: (0) the venue must serve `rfcVersion` `0.5.0-draft` (Riddler PR #1245, open; Riddler still serves `0.4.0-draft`, which every `0.5.0-draft` SDK refuses); (1) the producer withdraws; (2) old publishers and feed rings drain; (3) the narrowed `@xochi/solver-sdk` is published. A solver running it earlier on `HttpSolverTransport` MUST set `onInvalidEvent`; without it, a retained non-public entry ends `SolverClient.run`. A solver with an injected `SolverTransport` cannot set `onInvalidEvent` and must instead validate each event with `parseSolverEvent` in its transport. Consumer filtering is defence in depth, not the privacy boundary. Taker settlement types (`SPEC.md`) and every vector are unchanged; the version stays `0.8.1`. The `@xochi/solver-sdk` dev pin moves to `0.5.0`.
- **Version 0.8.1** (PATCH, no wire/vector change; SPEC.md §0.3), past every pre-fix commit (which declare the never-published 0.8.0). Riddler must advertise `spec_version: "0.8.1"` in lockstep, or the nightly `spec_version` probe reports DRIFT.
- `package.json` gains description, keywords and homepage.
- `package.json` declares `repository` with its `directory`, as `npm publish --provenance` requires; releases publish from `.github/workflows/release.yml` with provenance on a `spec-v*` tag.
- `engines.node` is `>=22`. `prepublishOnly` runs `format:check`, `typecheck` and `test` before every publish. The tarball ships this `CHANGELOG.md`.
- SPEC.md no longer links `docs/ARCHITECTURE.md`, which exists nowhere and shipped in no tarball; §5.2 and §9 still cite it by name.

### Fixed

- **Wire differ** (`wire/compare.mjs`): local `$ref` parameters and request bodies are resolved before grading served-only ones, so a required one is BREAKING, and every served `$ref` that is external, dangling, cyclic or malformed grades BREAKING wherever it sits (it graded STALE outside served-only parameters and request bodies); fragments decode in RFC 6901 §6 order.
- **`generate:wire`** grades against the `openapi.{json,sha256}` pair committed at HEAD, never the working tree, so a gutted, re-digested local copy cannot launder a BREAKING change; a committed pair that fails its digest is refused with no flag; `--first-vendoring` consents only to an unreadable or unrecognisable baseline (`unrecognisedContract`, shared with `verify:openapi`) and never skips the diff against an intact one; the document is renamed before the digest.
- Generator main-guards compare real file URLs, so `npm run generate:*` no longer no-ops in paths needing URL encoding.
